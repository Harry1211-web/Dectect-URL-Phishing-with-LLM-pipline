TRIỂN KHAI — API phát hiện phishing cho front end (FE)
======================================================

Mô hình
  FE (trình duyệt) --HTTPS--> Caddy (reverse proxy, cấp TLS) --> container "api" (uvicorn, src/api.py)
                                                               container "updater" (làm mới blocklist mỗi giờ)
  Hai container dùng chung ./data (blocklist, Tranco, cache, mẫu injection, log giám sát).
  API key của các lớp (OpenAI, VirusTotal) đọc từ ./.env (mount chỉ đọc).

Các endpoint
  POST /analyze   {"url": "...", "explain": false, "lang": "vi"}
                  -> {url, verdict: phishing | suspicious | clean, explanation, decided_by, latency_ms}
                  (chi tiết từng lớp "layers" chỉ trả về khi bật API_EXPOSE_LAYERS=1, xem bước 3)
  POST /feedback  {"url": "...", "label": "clean" | "phishing"}   (người dùng báo sai, không lưu URL)
  GET  /health    số URL / tuổi blocklist, classifier sẵn sàng, LLM / VirusTotal có bật không
  /docs           tài liệu API tương tác
  Mọi request POST phải có header  X-API-Key: <API_KEY>
  Mã lỗi: 401 thiếu / sai key, 413 body quá lớn (> 16 KB), 422 URL không hợp lệ (rỗng,
          javascript:, file:...), 429 vượt giới hạn tần suất, 503 server khởi động mà không có API_KEY.


0. Quyết định nơi giữ API_KEY
-----------------------------
Code chạy trong trình duyệt KHÔNG giấu được key (ai mở DevTools cũng thấy).
  - Nên làm: FE gọi backend riêng của FE, backend đó gắn header X-API-Key rồi chuyển tiếp sang
    API này. Key chỉ nằm trên server.
  - Demo / đồ án: để key trong FE, nhưng giới hạn CORS_ORIGINS đúng domain FE và giữ rate limit.
    Thiệt hại tối đa nếu lộ key bị chặn bởi LLM_BUDGET_USD trong .env.


1. Chuẩn bị server (Ubuntu VPS, RAM >= 2 GB)
--------------------------------------------
  curl -fsSL https://get.docker.com | sh
  git clone <repo> phishing && cd phishing     # models/url_classifier và data/injection_patterns có sẵn trong git
  nano .env                                    # OPENAI_API_KEY=...  VT_API_KEY=...  LLM_BUDGET_USD=...
  sudo chown -R 1000 data                      # container chạy với uid 1000


2. Chỉ cho proxy gọi được API
-----------------------------
Trong docker-compose.yml, service api:
    ports:
      - "127.0.0.1:8000:8000"      # thay cho "8000:8000": bên ngoài không gọi thẳng vào cổng 8000


3. Chạy
-------
  export API_KEY=$(openssl rand -hex 24)       # đưa cho FE (hoặc backend của FE)
  export CORS_ORIGINS=https://fe-cua-ban.com   # domain FE, nhiều domain thì cách nhau dấu phẩy
  export FORWARDED_ALLOW_IPS='*'               # chỉ an toàn vì cổng 8000 chỉ mở cho localhost (bước 2)
  docker compose up -d --build
  docker compose logs -f updater               # lần đầu tải feed + Tranco mất vài phút
  curl localhost:8000/health                   # "blocklist_stale": false là ổn

Tuỳ chọn (biến môi trường):
  RATE_LIMIT_PER_MIN   số request POST mỗi IP mỗi phút, tính riêng từng worker (mặc định 60; có 2 worker)
  USE_LLM=0            tắt Lớp D (không tốn tiền LLM; URL nghi ngờ giữ kết luận "suspicious")
  USE_VT=0             tắt tra cứu VirusTotal
  API_EXPOSE_LAYERS=1  trả thêm chi tiết từng lớp (điểm, ngưỡng của Lớp C...) — CHỈ dùng khi debug /
                       demo: kẻ tấn công có thể dò điểm để chỉnh URL lọt xuống dưới ngưỡng


4. HTTPS bằng Caddy (FE chạy HTTPS không được gọi API HTTP)
-----------------------------------------------------------
Trỏ bản ghi DNS api.domain-cua-ban.com về IP của VPS, rồi:
  sudo apt install caddy
  echo 'api.domain-cua-ban.com {
      request_body {
          max_size 16KB
      }
      reverse_proxy 127.0.0.1:8000
  }' | sudo tee /etc/caddy/Caddyfile
  # max_size: chặn body quá lớn ngay tại proxy (API cũng từ chối body > 16 KB có Content-Length)
  sudo systemctl reload caddy                  # Caddy tự xin chứng chỉ HTTPS


5. Gọi từ FE
------------
  async function checkUrl(url) {
    const ctrl = new AbortController();
    const t = setTimeout(() => ctrl.abort(), 30000);   // có LLM thì mất khoảng 2-15 giây
    try {
      const r = await fetch("https://api.domain-cua-ban.com/analyze", {
        method: "POST",
        headers: { "Content-Type": "application/json", "X-API-Key": API_KEY },
        body: JSON.stringify({ url, explain: true, lang: "vi" }),
        signal: ctrl.signal,
      });
      if (r.status === 422) throw new Error("URL không hợp lệ");
      if (r.status === 429) throw new Error("Gửi quá nhiều yêu cầu, thử lại sau 1 phút");
      if (!r.ok) throw new Error(`Lỗi ${r.status}`);
      return await r.json();
    } finally { clearTimeout(t); }
  }
  // Nút "Báo sai": POST /feedback {url, label: "clean" | "phishing"}

Hiện trạng thái đang tải. explain: true trả thêm lời giải thích ngắn bằng ngôn ngữ `lang` (tốn thêm
token); explain: false chỉ trả kết luận.

BẢO MẬT — mọi trường văn bản trong response phải hiển thị dạng TEXT, không bao giờ dạng HTML
(không dùng innerHTML / dangerouslySetInnerHTML / v-html). `explanation` do LLM viết sau khi đọc trang
của kẻ tấn công, các trường `reason` (khi bật API_EXPOSE_LAYERS) trích một phần URL: cả hai đều có
thể bị kẻ tấn công tác động. Server đã lọc link, thẻ HTML và số điện thoại khỏi `explanation`, nhưng
FE không được chỉ dựa vào đó. Không bao giờ biến URL đang bị cảnh báo thành link bấm được.


Chạy thử nhanh không cần server
-------------------------------
Windows (cmd):
  set API_KEY=k123
  set CORS_ORIGINS=http://localhost:5173
  uvicorn api:app --app-dir src --port 8000
FE chạy cùng máy gọi http://localhost:8000. FE đặt ở nơi khác thì mở tunnel HTTPS tạm thời:
  cloudflared tunnel --url http://localhost:8000
Không dùng Docker thì phải lên lịch làm mới blocklist mỗi giờ:
  schtasks /Create /SC HOURLY /TN PhishingBlocklist /TR "python <repo>\src\blocklist\updater.py"


Vận hành
--------
  docker compose exec api python src/monitoring.py report --days 7    # tỉ lệ báo nhầm / bỏ sót do người dùng báo
  git pull && docker compose up -d --build                             # cập nhật phiên bản mới
  Chi phí LLM: data/llm_spend.json (từ chối gọi khi chạm LLM_BUDGET_USD)
  Sức chịu tải: 1 request đầy đủ có thể tới ~25 giây; 2 worker x 40 luồng ~ 3 request/giây.
  Cần hơn thì tăng --workers trong Dockerfile hoặc thêm máy.
