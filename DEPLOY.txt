TRIỂN KHAI — hệ thống phát hiện phishing cho front end (FE)
==========================================================

Mô hình
  FE (trình duyệt) --HTTPS--> Caddy (TLS) --> container "bff" (bff/app.py, KHÔNG cần key)
                                                    | gắn X-API-Key (chỉ nằm trên server)
                                                    v  mạng nội bộ Docker
                                              container "api" (src/api.py, không mở ra ngoài)
                                              container "updater" (làm mới blocklist mỗi giờ)
  - FE KHÔNG BAO GIỜ giữ API_KEY. Chỉ BFF và API biết key, qua biến môi trường của server.
  - API không mở cổng ra ngoài: chỉ BFF trong cùng mạng Docker gọi được.
  - api và updater dùng chung ./data (blocklist, Tranco, cache, mẫu injection, log giám sát).
    Key của các lớp AI (OpenAI, VirusTotal) đọc từ ./.env (mount chỉ đọc vào api).

Vì BFF không đòi key, ai cũng gọi được BFF. BFF tự bảo vệ bằng:
  - Kiểm tra Origin: chỉ nhận request từ domain FE (FE_ORIGINS), cả CORS lẫn kiểm tra phía server
  - Giới hạn theo IP: BFF_RATE_PER_MIN (mặc định 10/phút) và BFF_RATE_PER_DAY (mặc định 300/ngày)
  - Tuỳ chọn Cloudflare Turnstile (CAPTCHA vô hình): chặn bot gọi thẳng BFF mà không qua trình duyệt
  - Ẩn lỗi nội bộ của API, không có /docs, giới hạn body 16 KB
  Chi phí tối đa vẫn được chặn bởi LLM_BUDGET_USD trong .env.

Các endpoint FE dùng (của BFF)
  POST /api/analyze   {"url": "...", "explain": false, "lang": "vi"}
                      -> {url, verdict: phishing | suspicious | clean, explanation, decided_by, latency_ms}
  POST /api/feedback  {"url": "...", "label": "clean" | "phishing"}   (người dùng báo sai, không lưu URL)
  GET  /api/health    {"ok": true | false}
  Mã lỗi: 403 sai Origin / thiếu hoặc sai Turnstile, 413 body quá lớn, 422 URL không hợp lệ (rỗng,
          javascript:, file:...), 429 vượt giới hạn phút / ngày, 502 dịch vụ phân tích lỗi,
          504 phân tích quá lâu, 503 server thiếu cấu hình.


1. Chuẩn bị server (Ubuntu VPS, RAM >= 2 GB)
--------------------------------------------
  curl -fsSL https://get.docker.com | sh
  git clone <repo> phishing && cd phishing     # models/url_classifier và data/injection_patterns có sẵn trong git
  nano .env                                    # OPENAI_API_KEY=...  VT_API_KEY=...  LLM_BUDGET_USD=...
  sudo chown -R 1000 data                      # container chạy với uid 1000


2. Chạy
-------
  export API_KEY=$(openssl rand -hex 24)       # bí mật giữa BFF và API — KHÔNG đưa cho FE
  export FE_ORIGINS=https://fe-cua-ban.com     # domain FE (nhiều domain thì cách nhau dấu phẩy)
  docker compose up -d --build
  docker compose logs -f updater               # lần đầu tải feed + Tranco mất vài phút
  curl localhost:8080/api/health               # {"ok": true} là ổn
Muốn giữ biến qua các lần khởi động: ghi API_KEY=... và FE_ORIGINS=... vào file .env cạnh
docker-compose.yml (docker compose tự đọc), không commit file này.

Tuỳ chọn (biến môi trường):
  BFF_RATE_PER_MIN / BFF_RATE_PER_DAY   giới hạn mỗi IP người dùng (mặc định 10 / 300)
  TURNSTILE_SECRET     bật Cloudflare Turnstile (xem bước 4)
  USE_LLM=0            tắt Lớp D (không tốn tiền LLM; URL nghi ngờ giữ kết luận "suspicious")
  USE_VT=0             tắt tra cứu VirusTotal
  MONITORING_KEEP_MONTHS  số tháng giữ log giám sát (mỗi tháng 1 file trong data/monitoring/,
                       mặc định 12; tháng cũ hơn tự xoá)
  API_EXPOSE_LAYERS=1  trả thêm chi tiết từng lớp (điểm, ngưỡng của Lớp C...) — CHỈ dùng khi debug /
                       demo: kẻ tấn công có thể dò điểm để chỉnh URL lọt xuống dưới ngưỡng


3. HTTPS bằng Caddy (FE chạy HTTPS không được gọi BFF bằng HTTP)
----------------------------------------------------------------
Trỏ bản ghi DNS api.domain-cua-ban.com về IP của VPS, rồi:
  sudo apt install caddy
  echo 'api.domain-cua-ban.com {
      request_body {
          max_size 16KB
      }
      reverse_proxy 127.0.0.1:8080
  }' | sudo tee /etc/caddy/Caddyfile
  sudo systemctl reload caddy                  # Caddy tự xin chứng chỉ HTTPS
  # max_size: chặn body quá lớn ngay tại proxy (BFF và API cũng tự từ chối)
Cổng 8080 của BFF chỉ mở cho 127.0.0.1 (docker-compose.yml): chỉ Caddy trên cùng máy kết nối được,
nên BFF tin header X-Forwarded-For của Caddy để biết IP thật của người dùng. Nếu đổi sang mở cổng ra
ngoài, phải đặt FORWARDED_ALLOW_IPS của bff thành IP của proxy, nếu không IP có thể bị giả mạo và
giới hạn theo IP bị vô hiệu.


4. (Khuyên dùng khi công khai) Chặn bot bằng Cloudflare Turnstile
-----------------------------------------------------------------
Giới hạn theo IP không đủ nếu kẻ tấn công có nhiều IP. Turnstile buộc mỗi request đến từ trình duyệt thật.
  a. Tạo widget miễn phí tại dash.cloudflare.com > Turnstile, khai báo domain FE.
     Được 2 khoá: site key (công khai, để ở FE) và secret key (bí mật, để ở server).
  b. Server:  export TURNSTILE_SECRET=<secret key>   rồi   docker compose up -d
  c. FE: nhúng widget, lấy token và gửi kèm header X-Turnstile-Token (mỗi token dùng 1 lần):
       <script src="https://challenges.cloudflare.com/turnstile/v0/api.js" async defer></script>
       <div class="cf-turnstile" data-sitekey="<site key>"></div>
       const token = turnstile.getResponse();   // sau mỗi lần gửi: turnstile.reset()


5. Gọi từ FE (không có key nào trong code FE)
---------------------------------------------
  const BFF = "https://api.domain-cua-ban.com";

  async function checkUrl(url, turnstileToken) {
    const ctrl = new AbortController();
    const t = setTimeout(() => ctrl.abort(), 45000);   // có LLM thì mất khoảng 2-15 giây
    try {
      const headers = { "Content-Type": "application/json" };
      if (turnstileToken) headers["X-Turnstile-Token"] = turnstileToken;
      const r = await fetch(`${BFF}/api/analyze`, {
        method: "POST", headers, signal: ctrl.signal,
        body: JSON.stringify({ url, explain: true, lang: "vi" }),
      });
      if (r.status === 422) throw new Error("URL không hợp lệ");
      if (r.status === 429) throw new Error((await r.json()).detail);   // giới hạn phút / ngày
      if (r.status === 403) throw new Error("Không xác minh được, tải lại trang và thử lại");
      if (!r.ok) throw new Error("Dịch vụ đang bận, thử lại sau");
      return await r.json();
    } finally { clearTimeout(t); }
  }
  // Nút "Báo sai": POST `${BFF}/api/feedback` {url, label: "clean" | "phishing"}

Hiện trạng thái đang tải. explain: true trả thêm lời giải thích ngắn bằng ngôn ngữ `lang` (tốn thêm
token); explain: false chỉ trả kết luận.

BẢO MẬT — mọi trường văn bản trong response phải hiển thị dạng TEXT, không bao giờ dạng HTML
(không dùng innerHTML / dangerouslySetInnerHTML / v-html). `explanation` do LLM viết sau khi đọc trang
của kẻ tấn công nên có thể bị tác động. Server đã lọc link, thẻ HTML và số điện thoại khỏi
`explanation`, nhưng FE không được chỉ dựa vào đó. Không bao giờ biến URL đang bị cảnh báo thành link
bấm được.


Chạy thử trên máy (không Docker)
--------------------------------
Hai cửa sổ cmd (Windows):
  1) set API_KEY=k123
     uvicorn api:app --app-dir src --port 8000
  2) set API_URL=http://127.0.0.1:8000
     set API_KEY=k123
     set FE_ORIGINS=http://localhost:5173
     uvicorn app:app --app-dir bff --port 8080
FE chạy cùng máy gọi http://localhost:8080/api/analyze. FE đặt ở nơi khác thì mở tunnel HTTPS tạm thời
tới BFF (và thêm domain tunnel vào FE_ORIGINS nếu FE chạy trên domain đó):
  cloudflared tunnel --url http://localhost:8080
Không dùng Docker thì phải lên lịch làm mới blocklist mỗi giờ:
  schtasks /Create /SC HOURLY /TN PhishingBlocklist /TR "python <repo>\src\blocklist\updater.py"


Vận hành
--------
  docker compose exec api python src/monitoring.py report --days 7    # tỉ lệ báo nhầm / bỏ sót do người dùng báo
  docker compose exec api python -c "import urllib.request as u; print(u.urlopen('http://localhost:8000/health').read().decode())"
                                                                      # chi tiết nội bộ (tuổi blocklist, LLM...)
  git pull && docker compose up -d --build                             # cập nhật phiên bản mới
  Đổi API_KEY: export API_KEY=<mới> && docker compose up -d   (BFF và API nhận cùng lúc; FE không đổi gì)
  Chi phí LLM: data/llm_spend.json (từ chối gọi khi chạm LLM_BUDGET_USD)
  Sức chịu tải: 1 request đầy đủ có thể tới ~25 giây; API 2 worker x 40 luồng ~ 3 request/giây.
  Cần hơn thì tăng --workers trong Dockerfile hoặc thêm máy.
